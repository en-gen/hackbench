### Changed

- Layer 3 on a settings byte $80 map with a Layer 3 Smash sprite loads where that sprite puts it, read from the ROM (#807): X is the sprite's X when it lies in $FF00-$00FF and $100 otherwise, Y is $A0 minus its Y (CODE_00FF61, bank_00.asm:14778-14803), instead of (0, $D0). Maps $01F and $1D4 now equal the captured frame 0, (256,160) and (112,160), and the map view shifts Layer 3 by its X. Evidence: layers_v5 frame 0, one machine; $1FC has the same sprite and no capture, so it changes by the same derivation unverified. Layer 3 is refused with a reason when the smash routine, its stub or init, the sprite loader or the start-up sweep is not the stock bytes (SHA-256 of the stock sites), when two smashers load, when the sprite is below $A0 (negative Y is not modelled), when the sprite stream has no terminator in its read, and when Mario's start X (entrance screen included) is $80 or more: camera X is taken as 0, which is traced only as far as CODE_05D83E (bank_05.asm:7164, the STZ Layer1XPos at :7170) and checked on three maps that start at $10, so the $80 boundary is unverified. The other 11 drawn maps of the fg gate set are unchanged (as recorded in the PR table, layers_v5 frame 0, one machine; the comparison method and baseline were not otherwise recorded). Evidence for the refusals: synthetic unit tests in L3Smash.test.ts, built from bytes in the test and so run in CI without a ROM, plant a change in each fingerprinted site (smash routine and its pointer, stub, init, position routine, sprite loader, start-up sweep) and expect a refusal, and cover two smashers, a sprite below $A0, a stream with no terminator and a start X of $80 (refused) against $7F (accepted); one corpus test, skipped without the corpus, patches one byte of the position routine on the vanilla ROM and expects a refusal. Refusal reason text is asserted only for the unreadable-sprites and the stub-only (fingerprint mismatch) cases; the others assert the refusal only.
