### Fixed

- Maps view (#967): when sprites, collision, block contents, a switch button or a palace block cannot be read or drawn, the toggle tooltip or note now says so in plain words ("this part of the map could not be read from the ROM.", "collision cannot be worked out for this map on this ROM.", "this map could not be read just now. Open the map again to try again.") and the technical error text sits on a second tooltip line (or the note's own tooltip), never in the accessible name or the visible note. That covers the castle-flame and block-content notes, the unverified-sprites tooltip, the start-position note and the palace block tooltips. A missing base ROM in these places, in the start-position note and in a screen error now all use the one sentence that says how to locate it again ("The base ROM ... is not on this machine. Choose File > Project Properties... and locate it again.").
- Maps view (#967): the plain "this part of the map could not be read from the ROM." wording for a map that cannot be built is now made once, in the shared map cache, so sprites, collision, block contents, the screen read and the switch buttons all show it with the technical text only in the tooltip. The map view's own separate wording for this case is gone.
