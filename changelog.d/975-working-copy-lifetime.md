### Fixed

- Opening a project whose base ROM file was renamed or deleted now shows it as not located everywhere, maps included, instead of drawing maps from a copy kept in memory (#975). Why: the backend kept each project's working copy for its whole life and never checked the ROM file again; open now checks the registered path still holds the project's ROM (same hash check as Project Properties, one per open) and, if not, drops the copy, tells open views, and answers not-located like any other server call. A server call that has to rebuild the copy (layers changed on disk) and finds the ROM gone drops it and tells open views the same way. Only an open checks (Open Recent, and Project Properties, which also opens): a ROM removed mid-session with no reopen still serves the held copy. Evidence: unit tests on synthetic carts (renamed, put back, mid-session, same instance when present). No Close Project command exists, so no release on close. HackBench ships as a desktop app whose backend ends with the app; the quit-and-relaunch claim is from the code (the registry is an in-memory field of the backend process), not from a launched build.
