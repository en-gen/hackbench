### Fixed

- Opening a project whose base ROM file was renamed or deleted now shows it as not located everywhere, maps included, instead of drawing maps from a copy kept in memory (#975). Why: the backend kept each project's working copy for its whole life and never checked the ROM file again; open now checks the registered path exists (no hashing) and, if gone, drops the copy and answers not-located like any other server call. Only an open checks: a ROM removed mid-session with no reopen still serves the held copy. A different ROM at the same path is caught by the existing identity check on a rebuild, not by this. Evidence: unit tests on synthetic carts (renamed, put back, mid-session, same instance when present). No Close Project command exists, so no release on close. HackBench ships as a desktop app whose backend ends with the app; the quit-and-relaunch claim is from the code (the registry is an in-memory field of the backend process), not from a launched build.
