# Side quest: one session, outside the orchestration

## Question

How does the owner put one session onto one specific problem without the BA, the teams and the board?

## Options considered

1. A protocol file under `docs/protocols/`, enacted with `/protocol`.
2. A per-session mode, stated in `CLAUDE.md`, that the owner switches on in that session's chat.

## Ruling

Verbatim, 2026-10-16: "scan this project for a side quest protocol and incorporate it into this project if you find it", pointing at Carina.Users. The rule ported from there is the owner's, 2026-10-14: "when I activate side-quest protocol, you don't follow the normal orchestration workflow designed for this project." and "I just want that one agent working on it. I don't want it delegated to a team through overwatch, etc." Option 2 follows from "that one agent" `[INF]`.

## Why

Protocols here apply to every session at once and `/protocol` nudges every registered session. A side quest is one session, so a protocol file would switch off the orchestration for the BA and every tech lead too.

## Applies to

`CLAUDE.md` (the side-quest bullet), `docs/protocols/README.md` (section Side quest), `.claude/skills/protocol/SKILL.md` (side-quest never goes through the script).
